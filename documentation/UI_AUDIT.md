# Zotero interface audit for 0.19.19

| Surface | Finding | Change |
| --- | --- | --- |
| Zotero Tags and the plugin’s tag browser | The two views share paper tags. The plugin mixed filtering the list of tag names with a second Search action, and native edits could leave open results stale. | Selecting tags updates results immediately, including during sync. Paper tags show their Zotero colors and can follow the automatic-tag visibility preference. A result can open its reference’s native Tags section. The plugin offers Paper tags, Page tags, and both, with Match all as the default. |
| PDF reader and Inbox tagging | Paper tags and page tags could look like separate stores or draw suggestions from the same mixed list. | The editor explains where each tag lives. The reader button names both scopes, paper suggestions use the Zotero vocabulary, and page suggestions use the linked-page vocabulary. The same paper-tag entry is available while filing from Inbox. |
| Linked papers and name review | The labels matched Zotero’s search modes, but a separate string matcher covered fewer fields and excluded notes and full text. Name review also made it hard to tell what a query would search. | The plugin runs Zotero’s native citation, fields and tags, and Everything searches, then restricts results to the current plugin view. Filenames searches Zotero attachment filenames and reMarkable names. Quoted native queries run on Enter. |
| Inbox, Import library, and choosers | Inbox had sorting and categories, but no text search. Folder and paper dialogs used a different search control, and the workspace shortcut could target a field behind an open dialog. | Inbox filters titles, filenames, and DOIs. Import exceptions and choosers use the same search control, term matching, and clear behavior. Ctrl+F and Ctrl+Shift+K target the visible search in the active dialog or view. |
| Workspace presentation and navigation | Fixed font sizes and full rerenders made some controls harder to follow at larger sizes or with the keyboard. Some search results used status text written for review decisions. | The workspace follows Zotero’s interface font-size preference, keeps its layout, and uses consistent focus indicators. Tag results update without rebuilding the tag picker on every selection. The native Tags handoff opens the selected paper directly. |

Zotero’s native Tags section, Tag Selector, and Advanced Search already provide library-wide editing and discovery, color assignment, saved searches, and collection scope. The plugin keeps the combined paper/page editor because reMarkable page tags are keyed to individual pages of linked PDFs. It reads Zotero paper tags and committed page maps for browsing, and uses the existing edit queue for linked changes.

The implementation reuses Zotero’s maintained, AGPL-3.0-or-later desktop search, tag, item-pane, and UI properties code. Both supported Windows builds, 10.0.6 and 10.0.8, expose these APIs. Zotero’s Local API also provides quick search, but its documented query modes and authorization requirements make it a poorer fit for an in-process workspace. A small local matcher remains useful for plugin-owned filenames, tag names, import paths, and folder paths. No additional library, device API, or installation step is required.
